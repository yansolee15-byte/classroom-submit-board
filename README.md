# 우리 반 제출 현황판 — v0.5 (Firebase 연결 준비본)

**학생용 v0.4 화면을 유지한 채, Firebase 연결 코드를 점검한 버전**입니다.

## 현재 상태

- 학생용 전체 현황판, 항목별 체크 팝업, 교사 관리 화면의 코드가 들어 있습니다.
- 데모 모드(가상 학생): `js/config.js`가 모두 비어 있으면 브라우저 로컬 저장소만 사용합니다.
- Firebase 모드: `js/config.js`에 실제 웹 설정과 교사 UID를 넣으면 Firebase SDK로 인증·Firestore 실시간 구독·저장을 시도합니다.
- **실제 Firebase 연결, Firestore 보안 규칙 게시, GitHub Pages 배포는 아직 완료되지 않았습니다.**
- 상태 변경 및 설정 검증 자동 테스트 **13개 통과**, 원격 Firebase E2E 테스트는 미실시.

## 가장 먼저 할 일

`SETUP.md`의 **A~D 단계**를 순서대로 따라 Firebase 프로젝트와 교사 계정을 만든 후, 이 폴더의 `js/config.js`에 구성 값을 채우세요. 비밀번호는 파일에 쓰거나 채팅에 보내지 마세요.

## 기능

- 학생 시작 화면: 로그인 화면 없이 제출 항목과 학생 **번호만** 표시. `?admin=1`은 학생 화면에 노출하지 않은 교사용 관리자 진입 주소입니다.
- 항목 카드 선택: 번호+이름이 표시되는 큰 팝업, 진행 중 허용에 따른 상태 순환, 취소/저장.
- 교사: 항목 추가·수정·보관·삭제, 학생 개별/일괄 등록, 학생별·항목별 현황, 일괄 상태 변경.
- Firestore: 각 학생·항목별 기록을 별도 문서로 저장. 학생 팝업에서 저장 전 상태를 확인하는 트랜잭션을 사용하여 **같은 학생의 동시 변경 덮어쓰기 위험을 줄임**. 실제 동시 접속 검증은 아직 필요합니다.
- Firebase 설정을 일부만 입력했으면 오류를 보여 주며, 실수로 데모 모드로 실행하지 않도록 했습니다.

## 로컬 데모

1. 폴더에서 `python -m http.server 8000` 실행.
2. `http://localhost:8000`으로 접속 (`file://` 더블클릭은 ES 모듈 제한으로 실패할 수 있음).
3. 가상 데이터에서 체크 → 저장 → 새로고침해 확인.
4. 교사용 데모: `http://localhost:8000/?admin=1`.

## 보안상 한계

학생은 로그인 화면이 없어도, 내부적으로 Firebase **익명 인증**을 사용합니다. 하지만 익명 인증은 실제 학생 신원을 확인하는 기능이 아닙니다. 링크를 아는 외부인도 익명 인증 후 학생 이름·제출 현황을 조회하거나 다른 학생의 상태를 변경할 수 있습니다. Firestore 규칙은 교사 전용 데이터 변경과 제출 상태 필드를 제한하지만, **실제 학생 실명 보호를 보장하지 않습니다.** 실명 등록 전 학교 승인·접근 제한 방안을 확인해 주세요. 자세한 내용은 `SECURITY_REVIEW.md` 참조.

## 테스트

Node.js가 있으면 `npm test` 실행. 현재 13개 단위 테스트 통과. 실제 Firebase 프로젝트/브라우저 연결 및 rules 적용 테스트는 별도 필요.

## 파일 구조

- `index.html`, `styles.css`: v0.4와 동일한 학생 화면 스타일
- `js/app.js`: 학생 팝업과 교사 관리 화면 동작
- `js/model.js`: 상태 순환·집계
- `js/store.js`: 데모 저장/Firestore 인증·구독·상태 변경
- `js/config.js`: Firebase 웹 설정 및 교사 UID **직접 입력 필요**
- `js/config-check.js`: 누락된 Firebase 설정 값 검사
- `firestore.rules`: 게시·검증 전 **규칙 초안**, UID 교체 필수
- `SETUP.md`, `PLAN.md`, `REQUIREMENTS.md`, `SECURITY_REVIEW.md`, `PROMPT_LOG.md`: 진행 안내·기록
